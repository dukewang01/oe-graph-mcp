# oe-graph-mcp

**酒店 OE（运营物资）盘点：本地校验 → 本地出图 → 脱敏指纹。**

一个 MCP server。装一次，之后你的 agent 就能读你自己的盘点表、
在你的机器上出一张交互图谱 HTML。

**你的文件不会离开你的机器。** 没有服务器，没有账号，没有上传，
代码里没有任何一行网络调用 —— 这一点你可以自己验证（见下）。

---

## 30 秒跑通

```bash
uvx --from . oe-graph-mcp        # 或者用你已有的 MCP 客户端配置接上
```

接上之后跟你的 agent 说：

> 用 oe_demo 生成样例跑一遍，让我看看装好了没。

它会生成一份**合成**盘点表（GBK 编码，模拟中文 Excel 导出）并出一张图。
打开那张 HTML，你会看到图谱 / 帕累托(ABC) / 风险 / 数据质量 四个视图。

没有样例数据也能玩。这一步的意义是：**先确认工具链是通的，再喂真数据。**

## 装到 MCP 客户端

### Hermes Agent

```bash
hermes mcp add oe-graph --command <python.exe> --args <repo>/oe_graph_mcp/server.py
```

### 直接指 `.py` 文件也可以

多数 MCP 客户端给的是一个「命令 + 参数」的框，指向文件比走 `-m` 更常见。
所以服务端**两种启动方式都支持**：

```bash
python /path/to/oe_graph_mcp/server.py      # ← 客户端常用这种
python -m oe_graph_mcp.server               # ← 需要 cwd 在仓库根
```

> 这一条是实测出来的：早期版本用了包内相对导入，直接指 `.py` 会
> `ImportError: attempted relative import with no known parent package`，
> 而且在客户端里是**静默失败**（只显示"没有这个工具"）。
> 现在 `server.py` 顶部会自己把仓库根加进 `sys.path`。

### Claude Desktop / Cursor / 其他（stdio 配置片段）

```json
{
  "mcpServers": {
    "oe-graph": {
      "command": "uvx",
      "args": ["--from", "https://github.com/<you>/oe-graph-mcp", "oe-graph-mcp"]
    }
  }
}
```

> **冷启动实测 2.5–4.8 秒**（本机实测：Hermes venv + mcp 2.0.0 = 2.5s；
> 系统 Python 3.14 + mcp 1.26.0 = 3.8s；裸解释器只占 0.29s）。
> 时间几乎全花在 **MCP SDK 自己的 import** 上 —— `mcp.server.lowlevel`
> 拉起 `jsonschema`，再拉起 `rfc3987_syntax` 这个正则模块，单项就吃掉 2.25s。
> **这部分不在本包的控制范围内**，做过 importtime 实测，不是猜的。
>
> 影响：客户端发现工具的窗口如果短于这个时间，会**静默忽略**本工具，
> 然后 agent 告诉你"没有这个工具"。遇到这种情况把客户端的启动/发现超时
> 调到 10s 以上即可。没法靠优化本包解决，所以写在这里而不是藏起来。

## 六个工具

| 工具 | 做什么 | 数据出本机? |
|---|---|---|
| `oe_spec` | 返回列头契约（标准本体，不含数据） | 否 —— 契约本身可以给任何人 |
| `oe_validate` | 用契约体检一张盘点表，产出分级问题清单 | 否 |
| `oe_build` | 本地生成单文件交互图谱 HTML | 否 |
| `oe_fingerprint` | 算脱敏指纹（比率、占比、档位标签） | **设计上可外发，但本工具不发送任何东西** |
| `oe_demo` | 生成合成样例并出图，用于自检 | 否 |

外加 `oe_selfcheck`：审计"这个包有没有网络调用"。**信任是算出来的，不是声明出来的。**

## 出错时返回什么（错误契约）

工具**不把异常甩给客户端**。任何失败都返回同一个形状：

```json
{"error": {"code": "E_FILE_NOT_FOUND", "message": "找不到文件: ...", "hint": "..."}}
```

| code | 含义 |
|---|---|
| `E_FILE_NOT_FOUND` | 路径不存在 |
| `E_IS_DIRECTORY` | 传的是文件夹，不是文件 |
| `E_PERMISSION` | 没权限，或文件正被 Excel / WPS 占用 |
| `E_BAD_INPUT` | 文件能打开但内容不合法（空表、整列错位等） |
| `E_INTERNAL` | 工具自身的缺陷（附反馈指引） |

为什么值得单列一节：调用你的通常是个 **agent**。给它一段异常栈，它分不清
"我路径写错了"和"这工具坏了"，只能反复重试或者放弃；给它一个 `code`，
它第一次就能自己改对。这是把工具交给 agent 用时和交给人的关键差别。

错误边界全包只有**一处**（`server.py` 的 `_safe`），所以以后新增的工具自动继承这个形状。

> **一个刻意的取舍**：出错时返回的是**正常结果**，不是 MCP 协议级的
> `isError: true`。因为构造协议级错误要依赖 SDK 的具体类型（1.x 和 2.x
> 不一样），而 1.x / 2.x 双兼容是这份代码的硬要求。带 `code` 的
> JSON 结果对 agent 更好用 —— 它能读到具体原因，而不是一句"工具执行失败"。
> 这一点是取舍，不是遗漏，所以写在这里。

## 验证：这些结论是怎么得到的

不是"应该能跑"，是实测过的。三个测试，任何人都能复现。

| 测试 | 命令 | 验证了什么 |
|---|---|---|
| 端到端冒烟 | `python tests/smoke.py` | GBK 探测、别名映射、包含回退、校验分级、建模、指纹白名单与零泄漏、错误路径 |
| 真握手 | `python tests/handshake.py <python> <server.py> <标签>` | 裸 JSON-RPC：`initialize` → `tools/list` → `tools/call`，**不用** MCP 客户端 SDK |
| 绘制路径 | `node tests/render_draw.js <图谱.html>` | 页面 JS 在无浏览器环境下执行；canvas 真的画了节点 / 边 / 标签；坐标无 NaN |

### 握手为什么不用 MCP 客户端 SDK

如果测试和服务端用同一个 SDK，"接得上"只证明这个 SDK 自己跟自己对得上。
用裸 JSON-RPC 走一遍，证明的是**协议层**对得上 —— 任何 MCP 客户端都能接。

### 绘制路径为什么必须单独测

一个离线单文件 HTML 最容易骗过人的地方是：页面能打开、侧栏有数字、
按钮能点，**但画布是空的**。DOM 层面的检查完全看不出来。
所以把页面里真正的 JS 抽出来，在 Node 的 `vm` 里跑，用一个"录音" canvas
上下文把每一次绘制调用记下来 —— 包括**送进去的坐标有没有 NaN**
（力导向布局最常见的崩法，在浏览器里表现为"什么都看不见"，肉眼极难定位）。

## 契约：你的表不用改名

多数"数据模板"工具要求你先把列头改成它规定的样子。这是免费工具最大的采用障碍 ——
改表这件事看起来很小，但足以让人关掉页面。

所以契约按**别名**匹配：

| 规范键 | 能认得的写法（部分） |
|---|---|
| `category` | 类别 / 分类 / 资产类别 / 物资类别 / 品类 / 大类 |
| `item` | 品名 / 物品名称 / 物料名称 / 资产名称 / 名称 |
| `outlet` | 营业点 / **营业部门** / 使用部门 / 归属部门 / 存放地点 / 点位 |
| `qty` | 数量 / **盘点数量** / 实盘数 / 数量(个) |
| `unit_price` | 单价 / 单价(元) / 单位成本 / 采购单价 |
| `vendor` | 供应商 / **供应商名称** / 供货商 / 厂商 |
| `amount` | 金额 / 总金额 / 原值 / 账面价值（**缺失时自动由 数量×单价 推导**） |
| `age_months` | 库龄月 / **使用月数** / 已用月数 / 库龄 |
| `status` | 状态 / **使用状态** / 资产状态（在用·闲置·破损·报废…） |

精确匹配不中时，还会做**包含关系回退**：`营业部门` 里有 `营业部`，所以能认出来。
推断出来的列头会**显式报告**（`I_HEADER_INFERRED`），不静默假装一切正常。

**认不出也不影响**：`类别` 的枚举只是建议，取值不在枚举里只产生 warning，不阻塞出图。
各家分类口径本来就不同，硬卡只会把人挡在门外。

### 必填 / 可选

- **必填**：`category` `item` `outlet` `qty` `unit_price` `vendor`
- **可选**：`spec` `amount` `age_months` `status` `asset_id` `last_count_date` `custodian`

只有必填齐全才出图。缺可选列时，相关指标显示 **N/A 而不是猜一个数**。

## 中文环境的坑（这些是专门处理过的）

| 坑 | 处理 |
|---|---|
| 中文 Excel 导出常是 **GBK**，按 UTF-8 读会乱码或直接崩 | 按 utf-8-sig → gbk → utf-16 顺序探测，并把**实际用的编码**回报 |
| 盘点表常有**合并标题行**、说明行在前 | 按"命中契约别名的数量"在前 12 行里找表头，不硬取第一行 |
| `1,234.00` / `¥1,234元` / `(1,234)` 会计负数 | 统一清洗为数值 |
| 空值写法五花八门：`-` `—` `无` `N/A` | 统一识别为缺失 |
| 全角括号 `（）`、不可见空格 | 表头归一化时清掉 |
| 单价差 50 倍（千分位/单位错误） | 与中位数比对，报 `W_PRICE_OUTLIER` |
| 表中含「责任人」这类**个人信息** | 默认移除该列，并给出 `W_SENSITIVE_COLUMN_PRESENT` 提醒 |

## 指纹：唯一被设计成可以外发的输出

想拿行业分位，就得让人把数字给你。所以定义清楚"什么可以出去"是关键。

指纹走**白名单**，不是黑名单 —— `spec.FINGERPRINT_FIELDS` 里没写的字段，
结构上就不可能出现在输出里，并且有运行时自检（越界直接 `AssertionError`）。

输出的全部是**比率、占比、档位标签**：

```json
{
  "spec_version": "1.0.0",
  "row_count_bucket": "1000-2000",
  "category_mix": { "不锈钢餐具": 0.0882, "玻璃器皿": 0.1471 },
  "value_per_room_band": "1500-3000",
  "defect_rate_band": "3-6%",
  "old_stock_share_band": ">30%",
  "outlet_count_bucket": "8-14",
  "vendor_count_bucket": "6-14",
  "has_status_column": true,
  "has_age_column": true
}
```

**不会出现**：供应商名、品名、单价、金额、责任人、资产编号、酒店名。

一个酒店的绝对值是商业敏感信息；"你在同类酒店里处于 P50–P75"不是。
所以指纹只带档位，不带数。
